# Kling Image O1 / Kling 3.0 Omni → MiniMax-H3 双路线

这是独立的路线 B Demo，不依赖 `Runway商品替换项目`。流程为：

```text
原视频首帧 + 商品参考图
→ Kling Image O1 替换商品
→ 人工确认中间图
→ 关键帧路径使用 MiniMax-H3；参考视频路径使用 Kling 3.0 Omni
```

两个付费阶段独立提交。图片成功后不会自动调用视频模型；视频失败或修改视频 Prompt 时，可以复用已经归档的替换首帧。

视频完成或失败后，历史 Run 中的按钮会变为“复用首帧重新生成视频”。每次点击都会创建一个新的 Run，复制原 Run 的输入与 `kling-output` 图片并记录 `derivedFromRunId`，只提交新的 H3 任务，不会重新调用 Kling，也不会覆盖旧视频。

## Runs 目录

每次点击“生成替换首帧”都会先创建一个独立 Run：

```text
runs/<run-id>/
├─ run.json
├─ events.jsonl
├─ inputs/
│  ├─ source-video/
│  └─ product-image/
├─ first-frame/
├─ kling-output/
└─ output/
```

`run.json` 保存输入、Prompt、模型、配置、阶段状态、Kling 图片任务 ID、新站 H3 视频任务 ID、请求摘要和原始响应。请求摘要不会保存 Base64 或 API Key。

每个派生 Run 都会复制 `kling-output` 中的本地归档图片，保证素材与运行记录完整。首帧模式提交时复用 Kling 公网结果 URL；参考视频模式通过 Cloudflare Quick Tunnel 提供临时公网素材 URL。`run.json` 中只保存脱敏占位符。

每个 Run 还包含两组可审计数据：

- `timing`：Run 开始时间、图片/视频阶段的开始、提交、完成时间，以及各阶段和总耗时（毫秒）。这些时间由服务端记录。
- `billing`：分别保存 Kling 与 H3 响应中的实扣金额、credits、tokens、输入/输出秒数、输入图片数和原始 usage。供应商没有返回的字段保持 `null`，不会用估算值冒充实扣值。

`billing.estimate.videoAmount` 是页面采用当前费率计算的 H3 预估费用；它和供应商返回的实际费用分开保存。视频类接口不一定采用 LLM token 计费，因此 `tokens: null` 是正常情况。完整供应商响应仍保存在 `imageLastResponse` 与 `videoLastResponse`，便于后续核账。

Xinhankr 在已有异步 H3 任务处于 `pending` 时，可能返回“账户余额不足 8 元”。协议探测显示这是固定的可用余额门槛或预留额度，不是 `duration × rate` 的最终价格。

## 配置与启动

在 `.env` 中填写：

```text
KLING_API_KEY=...
XINHANKR_API_KEY=...
MOCK_PIPELINE=false
```

启动：

```powershell
cd "C:\Users\17794\Documents\ChatGPT\项目\Kling-H3路线B项目"
npm start
```

日常使用直接双击 `启动服务.cmd`。它会把 Node 作为独立隐藏进程启动，PID 和日志保存在 `.runtime/`，不会依附当前终端或 Codex 任务。重复启动会复用已经健康运行的服务。需要关闭时双击 `停止服务.cmd`，脚本只会停止记录且校验属于本项目的 Node 进程。

打开 <http://127.0.0.1:8794/>。

首次建议将 `MOCK_PIPELINE=true`，验证上传、首帧提取、两阶段停点、轮询和 Runs 组织，不调用付费接口。

## 当前边界

- Kling 图片阶段使用 `kling-image-o1` 和两张图片：原首帧、商品图。
- 默认图片 Prompt 是不依赖商品类别的通用替换模板：区分场景图与商品参考图，锁定商品身份和内在设计，只允许调整整体姿态与场景光影，并根据手持、佩戴、接触或放置等实际画面条件保持物理关系。
- 默认视频 Prompt 不假设商品类型、人物、手持状态或口播内容；它以首帧为事实来源，约束主体和商品的时序一致性、物理支撑、接触遮挡及单镜头连续性。具体动作、台词或镜头需求可以在提交前追加。
- 视频模型按生成方式区分：`multi_keyframes` 在 Kling 替换关键帧后使用 `MiniMax-H3 / 768P`；`reference_video` 跳过关键帧替换，将原始商品图和原视频提交给 `Kling 3.0 Omni / 720P`。参考视频输出比例跟随原视频。
- `reference_video` 模式由 Electron 自动启动 Cloudflare Quick Tunnel，将本地商品图与参考视频的 `/media/...` 地址临时映射为公网 HTTPS URL 后提交 Kling。图片上限 10MB、视频上限 200MB，输入视频时长 3–10 秒；客户端关闭时通道随服务一并停止。
- 两条视频路径的实际费用均以供应商任务回执为准。
- Kling 3.0 Omni 使用 `prompt + base_video + refer_image` 请求结构，当前无付费验证仅覆盖本地 Mock 与既有独立 Demo 契约。
- Prompt 中指定中文台词不保证逐字准确；严格商业文案仍应使用 TTS 和 Lip-sync。
